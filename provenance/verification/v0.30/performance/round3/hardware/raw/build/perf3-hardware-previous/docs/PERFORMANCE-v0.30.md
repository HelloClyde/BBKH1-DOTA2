## 本轮开销与修改

未砍树时，重生计时函数在C3两个快照中每tick仅8个MIPS指令槽，不能解释持续掉帧。原VISION树木阻挡格与2113棵完整原树重建的8374个阻挡格逐位相同，未砍树的视线几何未因可交互树改变。主要已定位开销是动态视野阴影计算、每帧小地图查询和渲染。

1. 视野缓存8类最终0/1/2障碍平面，双缓冲树木字节平面在树版本变化时比较新旧成员，仅更新改变格且保留terrain-wall2和飞行规则；普通阴影查询直接读一个障碍字节，减少每格高度/区域/树位计算。缓存填满后，其他类别走原始region/height/flying判定，不反复重建整张平面。MIPS workspace为1,727,724字节，加139,264字节VISION负载共1,866,988字节。105场景/801,506项host检查、3,440,640字节迷雾记录与原实现相同，包含超过8类、负高度、未知高度、飞行、肉山区域和树木生命周期。
2. 小地图每帧读取一次只读current bitplane，替代5184次单点查询。576场景/75,202,560像素word对照相同；最终C7完整BDA的196,608格MIPS getter对照通过。
3. 树木贴图patch按相关瓦片的实际砍树状态失效；远处树变化不再让无关瓦片重复解码，同瓦片选树复用解码。颜色、深度和树冠选取输出的host对照通过。树变化仍会使视野tree_stamp整体更新，可能触发全局阴影重算，这部分尖峰尚保留。
4. 迷雾双像素RGB565算术保留C3原mix，3,145,728项算术和C5的97帧颜色/深度对照通过。C7 shader源码相同，guard由独立105场景迷雾等价验证；这是分层继承，未宣称C7重跑整套97帧。

曾测试的additive查表核在H1上更慢：相同1,048,576次叠加，原核12 raw ticks、查表16 raw ticks，两种先后顺序结果一致，已回退。微核时间不换算整机FPS。C5/C6中间候选的FPS和首个阵容错配拒绝报告也完整保留，不冒充C7最终验收。

最终C7与隔离CPU原型的BDA字节SHA完全相同；C6→C7相同Game快照预热2tick、测量8tick，Game/迷雾/单位可见性逐字节相同，指令槽减少3.94% / 3.26%。这不换算物理FPS，也不伪称最终ELF再跑CPU。

最终C7新跑视野54、树木2161项MIPS断言；资源读取100项MIPS检查来自C5，reader源码和接口未变，明确继承。C7真机完成两次正常树操作和清理；自然180秒完整长回的物理证据来自C3，C7长回规则由host/MIPS验证，未再等待当前BDA自然180秒。
