# v0.30 第三轮性能候选

C8 已完成标准 37 个编译单元构建及下述离线检查，尚未安装或取得真机 FPS。H1 保留 C7。当前 H1 原生资源管理器提示不能识别 B 卡，`B:\DOTA2\DOTA2.H1R` 的调试 stat 也失败；USB 调试本身状态正常。首次基线驱动因资源管理器位于前台而在桌面空闲检查处停止，没有启动游戏，不能记为 0 FPS。已请求检查 SD 卡、重启并恢复调试连接。

C8 BDA 为 `782aa7e90327e82204cb913fc3440e5789f0924301cbb07105defd6116350244`，1,083,444 字节；ELF 为 `dc6ecce5c66b0f1165ec637070a3beac35c89bb23cd6b96ae95b60cc69cd3b03`。私有 RAM 余量 22,720 字节，栈仍 65,536 字节。统一资源包仍是原来的 112,861,448 字节，SHA-256 `00ecddaf28bb3716cf9042115498b81e2b01363e66baa3e03b03b914be466153`，无需重新复制素材。

## 五项尝试

| 方案 | 结果与采用范围 |
| --- | --- |
| 已解码精灵热帧缓存 | 试过 2 MiB 可选池；相同 ELF 的 warm24 对照整帧指令量增加约 0.22%，撤回。实际 8 秒泉水序列涉及 164 帧、约 4.79 MB 原始帧，2 MiB 容易淘汰。8 MiB 尝试受诊断模型地址窗口限制，不能据此声称 H1 内存不足。现有 14 MiB 压缩帧池和 640 KiB 解码缓存保留。 |
| 透明行段 | 保留 128 条帧元数据，额外 220,140 字节 heap；跳过行首尾完全透明区域，行内仍逐像素透明混合及深度测试。独立对照精灵绘制指令量减少约 14.7%，整帧约 3.77%。未声称采用 IPU 或新增 SIMD 绘制。 |
| 阴影高度复用 | 保留平地路径，坡面、边界及世界坐标超出检查范围时仍用原高度采样。独立对照整帧指令量减少约 1.76%。原 24,576 字节阴影曲线移到可选 heap，空指针时使用完全相同的通道公式。 |
| 树变化的局部视野失效 | 保留。只推进未受变化格影响、且旧版本确实有效的源遮挡缓存；过期源和共享缓存仍保守失效。128 场景、1,001,735 项 host 检查及 4,194,304 字节迷雾对照相同。出兵后快照的远处树变化，重算 83→9 次；本次刷新 CPU 指令量减少约 73.29%，这个比例只描述树变化尖峰。工作区不增加。 |
| 资源索引、解码缓存及启动预热 | 试过 9 组缓存配置，保留 8 组索引页/4 个解码块的可选扩展，新增 168,336 字节 heap；失败回原 2/2。针对初始方向的 53 帧预热也做过独立重放：预热加初段 gameplay 的物理读 137→95，解码总量不变。这个预热实验省略地图、道具、音频竞争，未证明原生等待时间和净 FPS，暂不接入生产启动流程。 |

所有新增 heap 都有正常关闭路径。行段分配失败经过故障注入，精确回原绘制；阴影 scalar 路径通过主动释放曲线、使指针为空验证，未声称注入了曲线初始化 malloc 失败。未加入新的 `start_game` 预热、种子修改或模拟时间调整。

## 完整 C8 的限定对照

以下从相同的两份只读真机 Game 初始快照开始，普通逻辑预热 4 帧，再测量 2 帧，比较完整 C7/C8 BDA 的 MIPS API。C8 使用 128 条透明行段缓存和可选资源读缓存。两版对应帧的画面哈希、普通逻辑指令计数相同，关闭后模型 heap/文件句柄归零。没有执行原生入口、LCD、音频播放、MXU 或物理调度；MIPS 指令槽不等于耗时或 FPS。

| 初始快照 | C7 绘制指令槽 | C8 绘制指令槽 | 减少 |
| --- | ---: | ---: | ---: |
| 泉水 | 8,549,152 | 8,104,333 | 5.20% |
| 自然首波之后 | 9,294,533 | 8,852,016 | 4.76% |

另外，353 帧 renderer host 对照覆盖地图边缘、地形网格、10 名英雄和 16 个朝向，RGB565、深度、选取范围和绘制统计逐字节相同。它与完整 BDA 的 MIPS 检查是不同层次的证据。

完整 C8 已执行资源 104 项检查（含新增 MIPS32 描述符分配/迁移/释放）、视野 54 项、树木规则 2,161 项，以及 196,608 格 bitplane API 对照。局部树变化的 C7/C8 完整 Game 和迷雾对照另列原始报告，不代表整局功能或性能验收。

## 读盘计数与 IPU

冻结 C7 的正常 API 产生 320 帧菜单和 160 帧 gameplay 读序列，再用实际 C reader 重放，所有返回字节与原始逻辑资源相同。统计不包含实际音频流和 SD 延迟，不能换算 FPS。

| 阶段 | 原 2/2 读取次数 | 新 8/4 读取次数 | seek 前→后 |
| --- | ---: | ---: | ---: |
| 资源启动 | 1451 | 845 | 912→300 |
| 菜单 | 345 | 282 | 271→209 |
| 最初模型 8 秒 | 287 | 178 | 226→117 |

H1 的 JZ4740 IPU 用于 YUV/YCbCr 缩放、色彩转换和 RGB 输出，不能直接完成当前 RGB565＋透明度＋深度精灵合成。未写入 IPU、时钟或中断寄存器；[能力及原厂手册依据](IPU-v0.30.md)单独记录。

原始检查、失败尝试、冻结源码和范围限制见[第三轮证据](../provenance/verification/v0.30/performance/round3/INDEX.json)。当前设备上的 C7 帧率仍以[第二轮记录](PERFORMANCE-v0.30.md)为准；不得把此候选的离线百分比写成已经取得的真机帧率。
